FASE 1D — RECONCILIAÇÃO OPERACIONAL

1) Copie o arquivo:
   fase_1d_reconciliation.py
   para:
   app\api\reconciliation.py

2) Em app\main.py, adicione:

from app.api.reconciliation import router as reconciliation_router

E depois dos demais include_router:

app.include_router(
    reconciliation_router,
    prefix="/api/provisioning",
)

3) Compile:

python -m py_compile .\app\api\reconciliation.py .\app\main.py

4) Reinicie o Uvicorn.

5) Liste operações problemáticas:

Invoke-RestMethod `
  -Method Get `
  -Uri "http://127.0.0.1:8000/api/provisioning/operations?status=RECONCILIATION_REQUIRED" `
  -Headers @{ Authorization = "Bearer $TOKEN" } | ConvertTo-Json -Depth 10

6) Consulte a operação 5 (COMPENSATED):

Invoke-RestMethod `
  -Method Get `
  -Uri "http://127.0.0.1:8000/api/provisioning/operations/5" `
  -Headers @{ Authorization = "Bearer $TOKEN" } | ConvertTo-Json -Depth 10

7) Reconcile a operação 5:

Invoke-RestMethod `
  -Method Post `
  -Uri "http://127.0.0.1:8000/api/provisioning/operations/5/reconcile" `
  -Headers @{ Authorization = "Bearer $TOKEN" } | ConvertTo-Json -Depth 10

O esperado para a operação 5 é:
- status COMPENSATED
- reconciled true
- avaya_state ABSENT
- action NONE

IMPORTANTE:
- A reconciliação NÃO executa DELETE automático quando encontra um usuário presente no Avaya.
- Falhas sem GUID nunca são promovidas automaticamente a COMPLETED.
- O único fechamento automático para COMPLETED nesta fase é o caso CACHE_PERSISTENCE_FAILED quando o GUID é encontrado e o cache pode ser reparado.
